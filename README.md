# Aletheia — Unsafe Transaction Types for Aiken

An Aiken library that provides unwrapped transaction types that survive serialization through Plutus Data, plus conversion functions into the stdlib.

## What it does

Aiken's `cardano/transaction.Transaction` is opaque. It enforces internal invariants (`Value` canonical ordering, uniqueness guarantees, etc.) that make it impossible to round-trip through `serialise` / `deserialise`. If you try to `deserialise` a stdlib `Transaction` from Plutus Data, the compiler rejects it.

This is a problem when you want to test validators against **real transaction data** from the blockchain. You can't just serialize a transaction off-chain, paste it into Aiken, and `deserialise` it.

Aletheia solves this by providing **unsafe** types built from only simple structures — plain records, lists, pairs, and primitives — that carry the same data as their stdlib counterparts but without the hidden invariants. These types:

- Compile to the same Plutus Data shape as the off-chain TypeScript schemas used by [Hermes](https://github.com/txpipe-shop/hermes).
- Can be `deserialise`d from CBOR generated by Hermes (or any tool that outputs matching Plutus Data).
- Can be converted into the standard stdlib `Transaction` via the `convert` module, so your validators work with the familiar types.

In short: Aletheia is the on-chain half of the Hermes workflow. Hermes exports CBOR; Aletheia deserializes and converts it.

```
┌────────────────────────────────────────────────────────────────┐
│  TypeScript (off-chain)                Aiken (on-chain)        │
│                                                                │
│  Raw TX CBOR                       deserialise CBOR            │
│       │                                  │                     │
│       ▼                                  ▼                     │
│  ┌──────────────┐                 ┌──────────────────┐         │
│  │ Hermes       │                 │ UnsafeTransaction│         │
│  │              │  serialize ───▶ │ (aletheia)       │         │
│  │ UnsafeTx obj │   to CBOR       │                  │         │
│  └──────────────┘                 └────────┬─────────┘         │
│                                            │                   │
│                                            │ convert.ak        │
│                                            ▼                   │
│                                  ┌──────────────────┐          │
│                                  │ Transaction      │          │
│                                  │ (stdlib)         │          │
│                                  └──────────────────┘          │
└────────────────────────────────────────────────────────────────┘
```

## Installation

Add aletheia as a dependency:

```sh
aiken add txpipe-shop/aletheia --version 0.1.1
```

Then import it in your Aiken code:

```aiken
use aletheia/unsafe_transaction.{
  UnsafeTransaction
}
use aletheia/convert.{
  unsafe_transaction_to_transaction
}
```

## Usage

Aletheia is designed to be used alongside test code generated by [Hermes](https://github.com/txpipe-shop/hermes). Hermes emits `.ak` files that contain the serialized transaction CBOR, typed datum/redeemer constants, policy hashes, certificate data, and validator calls — everything needed to reconstruct the script context.

When you provide Hermes with a project config ([`hermes.json`](https://github.com/txpipe-shop/hermes#project-configuration-hermesjson)), it generates a **complete, ready-to-run test file**. Hermes auto-detects datum and redeemer types from your project's `plutus.json` (generated by `aiken build`). A minimal config is just:

```json
{
  "validators": {
    "<script-hash>": {
      "module": "my_validator",
      "name": "my_validator"
    }
  }
}
```

This produces a fully typed test file with aliased imports to prevent name clashes:

```aiken
use aiken/cbor.{deserialise}
use aletheia/convert.{unsafe_transaction_to_transaction}
use aletheia/unsafe_transaction.{UnsafeTransaction}
use cardano/certificate.{Certificate}
use cardano/transaction.{OutputReference, Transaction}
use cardano/address.{Script}
use my_project/types.{MySpendRedeemer, MyMintRedeemer, MyPublishRedeemer} as my_project_types
use my_validator

const tx_ut: Transaction = {
  expect Some(unsafe_tx_data) = deserialise(#"d8799f...")
  expect unsafe_tx: UnsafeTransaction = unsafe_tx_data
  unsafe_transaction_to_transaction(unsafe_tx)
}

// Spend datum: wrapped in Option<Type> — Some(r) when present, None when absent
const spend_1_datum: Option<MySpendDatum> = {
  expect Some(d) = deserialise(#"d87980")
  expect r: MySpendDatum = d
  Some(r)
}

// Datum absent:
// const spend_1_datum: Option<MySpendDatum> = None

const spend_1_redeemer: MySpendRedeemer = {
  expect Some(d) = deserialise(#"d87980")
  expect r: MySpendRedeemer = d
  r
}

const spend_1_ref = OutputReference {
  transaction_id: #"abc123...",
  output_index: 0,
}

const mint_1_redeemer: MyMintRedeemer = {
  expect Some(d) = deserialise(#"d87980")
  expect r: MyMintRedeemer = d
  r
}

const mint_1_policy = #"05a338ab..."

const publish_1_redeemer: MyPublishRedeemer = {
  expect Some(d) = deserialise(#"d87980")
  expect r: MyPublishRedeemer = d
  r
}

const publish_1_cert: Certificate = {
  expect Some(d) = deserialise(#"d87980")
  expect r: Certificate = d
  r
}

test buy_nft() {
  and {
    my_validator.spend(owner_pkh, nft_policy, spend_1_datum, spend_1_redeemer, spend_1_ref, tx_ut),
    my_validator.mint(owner_pkh, nft_policy, mint_1_redeemer, mint_1_policy, tx_ut),
    my_validator.publish(owner_pkh, nft_policy, publish_1_redeemer, publish_1_cert, tx_ut),
  }
}
```

You can also explicitly specify types in `hermes.json` to override auto-detection, or add `params` to pass arguments to parameterized validators. Supported purposes are `spend`, `mint`, `withdraw`, and `publish`. See the [Hermes docs](https://github.com/txpipe-shop/hermes#project-configuration-hermesjson) for the full config reference.

> **Note:** `votes` and `proposal_procedures` are hardcoded to empty defaults during conversion since they are typed as `Never` in `UnsafeTransaction`.
